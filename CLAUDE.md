# Atlas des Empires — contexte pour Claude

Chargé automatiquement au début de chaque session Claude Code, sur toutes les machines (versionné dans git). À garder court : il est relu à chaque session. Le détail est dans `docs/`.

## Le projet
Carte interactive (React + Vite + TS strict + MapLibre GL, relief 3D) qui montre étape par étape l'évolution d'empires : frontières qui glissent (SDF + shader en custom layer), batailles, armées, personnages, mode Histoire narré, chatbot ADK.
- Architecture : `docs/ARCHITECTURE.md`. Agent ADK (Python, `agent/`) : `docs/AGENT.md`. Lancement et tests : `README.md`.
- Contrat de données : `src/types.ts`. Données : `data/empires/<id>/timeline.json`, `data/cities.json`, pipeline géo `scripts/` → `public/data/empires/<id>/`.
- Ajouter un empire : skill `.claude/skills/ajouter-un-empire/` (historien, puis carte + front + figurines). Un nouvel empire doit aussi avoir `people.json`, `profile.json`, `inventions.json` et `regions.json`.
- Principe : tout calcul géométrique coûteux (découpe, simplification, diffs, SDF) se fait au build dans `scripts/`, jamais dans le navigateur. Un empire est détecté automatiquement depuis son dossier `data/empires/<id>/` (pas de code à changer).

## Commandes
- Dev : `npm run dev` (5173, ou config `dev` de `.claude/launch.json`). Prod locale : `npm run serve` (4173).
- Avant de pousser, comme la CI : `npm run typecheck && npm run lint && npm run format:check && npm test && npm run test:data`, puis `npm run test:e2e` et `npm run check:bundle` si l'UI ou les imports changent.
- Un seul test : `npx vitest run tests/unit/march.test.ts -t "<nom>"` ; `npx playwright test e2e/map.spec.ts -g "<nom>"`. Les e2e font `npm run build` puis servent sur 4173 (un serveur déjà lancé sur 4173 est réutilisé : il doit être à jour).
- Données géo : `npm run fetch:data` (une fois, dans `.cache/`), puis `npm run build:data` ou `build:data:<id>` (rome, napoleon, china, mongols, espagne, saint-empire, carolingiens, alexandre). Relancer Vite ensuite.
- Agent : `npm run agent` (port 8000), `npm run agent:test`.

## État (à mettre à jour en fin de session)
- Sur `main` : Rome, Napoléon, Chine, Mongols, Espagne, Saint-Empire, Carolingiens, Alexandre (cartes de ces trois derniers composées depuis `overrides/<id>/_carto.json` par `scripts/empires/fromCarto.ts`, apogée forcée par `apogee` dans la timeline si la plus grande surface trompe) ; chatbot ADK (le « sage », Gemini ou Claude via `ATLAS_MODEL`) ; apogée sur la frise ; régiments animés (marche proportionnelle à la distance, `src/lib/march.ts`) ; empires contemporains ; carte du monde entière ; formulaire « Votre avis » (mailto) ; villes de départ des armées (`from`, `src/lib/origin.ts`) ; personnages illustres (`data/empires/<id>/people.json`, galerie, outil `chercher_personnage` du sage) ; monuments (`data/monuments.json`, calque, éventail des piles ; 7 merveilles antiques `wonder: true` : icône dorée hors piles, bandeau et filtre en galerie) ; routes commerciales (`data/routes.json`) et catastrophes/guerres (`data/disasters.json`) ; vue « Le monde en l'an X » (`src/world/`, `?world=1&year=`) ; quiz du sage (`agent/atlas_agent/quiz.py`, `src/quiz/`) ; comparaison de deux empires (`src/compare/`, `?compare=a,b`, profils `data/empires/<id>/profile.json`) ; inventions révolutionnaires (`data/empires/<id>/inventions.json`, calque, frise, galerie, comparaison, outil du sage) ; piles d'icônes monuments + inventions réunies dans un seul éventail (`src/map/pileFan.ts`) ; capitales des voisins (`data/capitals.json` → `build-neighbors`, points `kind: 'capital'`) et des empires contemporains (`capitalOf` de `data/cities.json`, anneau dans le calque des villes). Cadre des voisins de la Chine et des Mongols : `NEIGHBOR_BOUNDS` dans `scripts/build-neighbors.ts`. Régions survolables et cliquables à l'arrêt (`territory-hover`, `src/map/regionCard.ts`, textes `data/empires/<id>/regions.json`, liste via `scripts/list-regions.ts`). Page « Tous les empires » (`src/empires/`, `?empires=1&e=`). Mode « Devine la suite » (`src/guess/`, `player.guess`/`asking`). « Voir la bataille » (`src/battle/`, chunk lazy, canvas) : batailles jouables = clés de `data/battles/troops.json`, scénarios historiques `data/battles/scenarios/<stepId>.json` (contrat `src/types-battle.ts`), sinon simulation générique (`genericScenario`). Combat : poses `vise`/`recharge`/`baionnette` (`src/battle/poses.ts`, 4e paramètre de `soldierSvg`), armes à feu déduites des dessins (`src/battle/weapons.ts`), artillerie (`cannon.ts`), effets (fumée, éclairs, boulets, flèches) calculés depuis `t` dans `engine.ts` ; `action: 'feu' | 'baionnette'` dans les scénarios. Décor : `biome` par bataille dans `troops.json`, mise en page pure `src/battle/layout.ts` (`sceneryLayout`), dessin `scenery.ts` (sol précalculé hors écran, arbres triés avec les figurines). Ouvrir une bataille met la lecture en pause et fige l'étape (`App.tsx`). Chargement à la demande : index `virtual:empire-index` (`build/empireIndex.ts`), `loadEmpire`/`loadAllEmpires`, `loadWorld` ; budget JS initial 465 Ko gzip (la CI compresse ~2 Ko de plus qu'en local ; figurines dans le JS initial) (`npm run check:bundle`). Style : Prettier + oxlint (`npm run lint`, `format`). Tests : un par grosse fonctionnalité (17 e2e, données groupées via `itAll`).
- Hébergement gratuit : `npm run serve` (local + réseau domestique) ; **en ligne** sur GitHub Pages (https://florentgru.github.io/empires-map/, chaque push sur `main` déploie) via `.github/workflows/pages.yml` (build `VITE_STATIC=1`, sans sage ; quiz hors ligne en TS `src/quiz/offline.ts`).
- SEO : adresses lisibles `/<empire>/<étape>/` et pages de synthèse `/empires/`, `/monuments/`, `/personnages/`, `/inventions/` (`src/lib/seo.ts`, partagé ; anciennes adresses `?empire=&step=` encore comprises, `src/player/urlState.ts`). `npm run build` pré-rend 262 pages HTML (`scripts/prerender.ts` : tête, Open Graph, JSON-LD, article lisible sans JS) + sitemap, robots, llms.txt, 404. Images de partage et icônes : `npm run build:og` (PNG commités dans `public/og/`). Polices hébergées (`@fontsource`, plus de Google Fonts).
- À faire par l'utilisateur : renseigner son adresse dédiée dans `src/config.ts` (`FEEDBACK_EMAIL`, publique)  ; déclarer le site et `sitemap.xml` dans Google Search Console et Bing Webmaster Tools.

## Règles de travail
- Répondre en français. L'utilisateur se forme au métier d'ingénieur IA : expliquer les choix.
- Commit + push après chaque changement, mais **jamais un commit qui casse la CI** (Florent reçoit un e-mail à chaque échec) : vérifier typecheck + tests en local avant de pousser. CI GitHub seulement sur `main` et les PR.
- Toute nouvelle vue ou page indexable passe par `src/lib/seo.ts` (adresse, titre, description) et `scripts/prerender.ts` (page statique + sitemap).
- Ne jamais créer, lire ni manipuler de clé API (l'utilisateur la met lui-même dans `agent/.env`).
- Sous-agents : modèle Sonnet, peu nombreux, séquentiels (parallèles seulement sur fichiers disjoints), prompts précis.
- Économie de tokens : ne jamais lire en entier les gros JSON/GeoJSON (extraits via `node -e`), peu de captures.
- Captures : Chromium du projet (`@playwright/test`) en headless ; l'utilisateur juge la fluidité dans son navigateur (Brave).
- Le serveur Vite doit être relancé après régénération de `public/data` ; ne pas utiliser `pkill -f` avec un motif qui correspond à la commande elle-même.
- Deux machines : Linux (ce PC, Node installé) et un PC Windows (`C:\Users\fgru\project\empires-map`, sans Node). `git pull` en début de session.
